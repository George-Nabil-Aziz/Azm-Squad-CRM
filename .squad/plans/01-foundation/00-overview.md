## Dependency notes

- **Story 01 (CRM-1)** creates `server/` and `client/`; every other story in every feature depends on it.
- Shared contract: the API runs on `http://localhost:5080` (launchSettings `http` profile) and the Vite proxy in `client/vite.config.ts` points to it. Change both together.
- **Story 02 (CRM-5)** defines the error contract every later story uses: ProblemDetails with `correlationId`, `X-Correlation-Id` header, Application exceptions (`ValidationException`, `NotFoundException`, `ConflictException`, `ForbiddenException`) + `ValidateOrThrowAsync`, the shared `CrmApiFactory` test host, and the client `ApiError` / `onApiError` → sonner toast. CRM-3 swaps the sonner `Toaster` for the shadcn wrapper (one import); CRM-4 moves `client/src/api/error-messages.ts` to i18n.
- **Story 03 (CRM-2)** adds persistence and auth: `CrmDbContext` (Identity, `Guid` keys) + migration `InitialIdentity`, `Database:StartupAction` (`Migrate` in Development, `EnsureCreated` in tests), seeded roles + `admin@crm.local`, `POST /api/auth/login` and `GET /api/auth/me`, JWT claims `sub`/`email`/`name`/`role`, the rule "every `/api/*` endpoint declares `RequireAuthorization()` or `AllowAnonymous()`" (guard test), `CrmApiFactory` with SQLite + `FakeTimeProvider` + `LoginAsync`/`CreateAuthenticatedClient`, and the client `client/src/auth/` module (401 never toasts; 401 on a signed-in call clears the session). CRM-3 replaces the minimal sign-in form with the styled login page and routing; CRM-6/CRM-7 build users and permissions on `ApplicationUser`, `Roles` and the `role` claim.
- **Story 04 (CRM-3)** sets up the frontend shell every later page plugs into: Tailwind v4 + shadcn/ui (`components.json` style `radix-nova`, `rtl: true`, CLI pinned to `shadcn@4.21.2`, `@/` alias), theme colors as CSS variables in `client/src/index.css`, `react-router` routes in `client/src/app/AppRoutes.tsx` (`RequireAuth` → `/login`), sidebar items in `client/src/app/navigation.ts` (unbuilt areas route to `ComingSoonPage`), layout in `client/src/components/layout/`, React Query via `createQueryClient()` (cache cleared on sign-out), the styled login page (react-hook-form + zod), `client/src/test/fake-api.ts`, and the guard tests in `client/src/theme.test.ts` (no hex colors, logical direction classes). Feature stories replace their `ComingSoonPage` route; CRM-4 moves `client/src/app/messages.ts` + `auth-messages.ts` to i18n and sets sidebar `side`/`dir`; CRM-7 filters `navigationItems` by permission.
- **Story 05 (CRM-4)** makes the app bilingual: every UI string lives in `client/src/i18n/{en,ar}.json` (typed keys via `client/src/i18n/i18next.d.ts`), `client/src/i18n/i18n.ts` (`getLanguage`, `setLanguage`, storage key `crm.language`) keeps `<html lang dir>` in sync, `LanguageSwitcher` sits on the login page and in the header, the sidebar moves to the right in Arabic, `DirectionProvider` wraps the app, and `client/src/api/client.ts` sends `Accept-Language`. Guards: `translations.test.ts` (same keys, Arabic values, same placeholders) and `no-hardcoded-text.test.ts`. Server: `AddCrmLocalization` / `UseCrmLocalization` (header only, UI culture `en`/`ar`, **before** `UseCrmErrorHandling`), `LocalizedText.Get(english, arabic)` and static `<Feature>Text` classes in `Crm.Application` guarded by `LocalizedTextCatalogTests`; FluentValidation messages, ProblemDetails titles and the wrong-credentials detail follow `Accept-Language`. Every later story adds its strings to both JSON files (client) and to a `<Feature>Text` class (server).
