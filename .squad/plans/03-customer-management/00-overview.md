## Dependency notes

- **Every story here builds on the foundation feature** ([../01-foundation/00-overview.md](../01-foundation/00-overview.md)): ProblemDetails + Application exceptions (CRM-5), `CrmDbContext` / migrations / `TimeProvider` / `CrmApiFactory` (CRM-2), shadcn layout + routes + React Query (CRM-3), ar/en i18n + `<Feature>Text` server texts (CRM-4) — and on **security-admin** ([../02-security-admin/00-overview.md](../02-security-admin/00-overview.md)): `PagedResult<T>` + `PagingDefaults`, the users page as UI precedent (CRM-6), the permissions `customers.view` / `customers.manage` (every seeded role has both), `RequireAuthorization(Permissions.X)`, the guards in `PermissionPolicyTests`, client `<Can>` / `RequirePermission` (CRM-7).
- **Story 08 (CRM-8)** adds the first Domain entity and the shared pieces later stories reuse: `Crm.Domain.Customers.Customer` (primary `Email` / `Phone` columns, UTC timestamps passed in, soft delete), `Crm.Domain.Common.ISoftDeletable`, the named query filter `CrmDbContext.SoftDeleteFilter` + guard `EverySoftDeletableEntity_HasTheSoftDeleteQueryFilter`, the UTC `DateTime` convention (`UtcDateTimeConverter`), `IEntityTypeConfiguration<T>` classes in `Crm.Infrastructure/Persistence/Configurations/`, the Application-service + Infrastructure-repository pattern (`CustomerService` / `ICustomerRepository` / `CustomerRepository`), `LikePattern`, `PagingText`, migration `AddCustomers`, `/api/customers` endpoints; client `client/src/api/paging.ts` (`PagedResult`, `ListParams`, `listPath`), `apiDelete`, `client/src/api/customers.ts`, the Customers page in `client/src/pages/customers/` + `client/src/features/customers/`.
- **Story 09 (CRM-9)** adds contact details: `ContactType` + `CustomerContact` owned by `Customer` (`OwnsMany` → table `CustomerContacts`; many phones / emails / WhatsApp numbers, one primary per type enforced by the aggregate; `Customer.Email` / `Customer.Phone` stay as the denormalized primary values), E.164 normalization with **libphonenumber-csharp 9.0.40** in `ContactValues.TryNormalizePhone` (Application; default region `SA`, Arabic-Indic digits accepted), routes `POST /api/customers/{id}/contacts`, `POST …/contacts/{contactId}/primary`, `DELETE …/contacts/{contactId}`, the exact-match lookup `GET /api/customers/lookup?phone=|email=` = `ICustomerService.LookupAsync` (**the email / WhatsApp channels CRM-23..26 call it to match incoming messages**), `contacts` in `CustomerResponse`, migration `AddCustomerContacts` (schema + data copy of the CRM-8 columns as primary contacts); client `getCustomer` / `useCustomer(id)`, the contacts dialog (`CustomerContactsDialog`, `CustomerContactsTable`, `AddContactForm`) and the shadcn `native-select` component. Details: section "6 — How later stories build on this" in [09-story-customer-contacts-CRM-9.md](09-story-customer-contacts-CRM-9.md).
- **Story 10 (CRM-10)** adds the customer timeline: Domain `CustomerInteraction` (table `CustomerInteractions`, `long` identity key, `Type` = `InteractionType` Customer / Note / Attachment / Ticket / Message, `Event` code from `InteractionEvents`, `Details`, `SourceId`, `ActorId`, UTC `OccurredAt`), the Application **`IInteractionRecorder`** every later feature calls before its `SaveChangesAsync` (same unit of work), `GET /api/customers/{id}/timeline?type=&page=&pageSize=` (newest first, `customers.view`), migration `AddCustomerInteractions`; client details page `customers/:id` (`CustomerDetailsPage`, `CustomerTimeline`, `useCustomerTimeline`). **CRM-10 AC 2 (ticket created → timeline entry) is completed by CRM-13.** Details: section "5 — How later stories build on this" in [10-story-customer-timeline-CRM-10.md](10-story-customer-timeline-CRM-10.md).
- **Story 11 (CRM-11)** adds `CustomerNote` / `CustomerAttachment` (tables `CustomerNotes`, `CustomerAttachments`), the file abstraction **`IFileStorage`** (`Crm.Application/Common/Files`) with `LocalFileStorage` (root `FileStorage:RootPath`, default `%LOCALAPPDATA%/AzmSquadCrm/files`, keys `customers/{customerId:N}/{attachmentId:N}`), `AttachmentRules` (10 MB, extension allow-list, server-side content type), routes `/api/customers/{id}/notes` and `/api/customers/{id}/attachments[/{attachmentId}]` (download behind `customers.view`), timeline events `noteAdded` / `attachmentAdded`, migration `AddCustomerNotesAndAttachments`; client `apiPostForm` / `apiGetBlob`, `saveFile`, notes and attachments sections on the details page. Ticket / email attachments reuse `IFileStorage` + `AttachmentRules`. Details: section "5 — How later stories build on this" in [11-story-customer-notes-attachments-CRM-11.md](11-story-customer-notes-attachments-CRM-11.md).
- **CRM-10 / CRM-11** hang child entities (FK `CustomerId`, `Restrict`) and routes `/api/customers/{id}/…` off the customer; a deleted customer answers 404. **Tickets (CRM-13)** reference `CustomerId` with `Restrict` and must read customers with `IgnoreQueryFilters([CrmDbContext.SoftDeleteFilter])` so tickets of soft-deleted customers stay visible (CRM-8 AC 5).
